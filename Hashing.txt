✅1. Two Sum (Hash Map / One Pass Lookup)

    Explanation: Given an array of integers and a target value, return the indices of two numbers such that they add up to the target.

    Input: nums = [2,7,11,15], target = 9

    Output: [0,1]

    Clarifying Questions For Interviewer:
    1. Is exactly one valid answer guaranteed?
    2. Can the array contain duplicate values?
    3. Can numbers be negative?
    4. Can we use the same element twice?
    5. Should we return indices or values?

    ==================================================

    BRUTE-FORCE

    Idea: Check every possible pair and see if their sum equals target.

    Steps:
    1. Pick first element
    2. Compare with every next element
    3. If sum equals target, return indices

    Python Code:

    class Solution:
        def twoSum(self, nums, target):

            for i in range(len(nums)):

                for j in range(i + 1, len(nums)):

                    if nums[i] + nums[j] == target:
                        return [i, j]

    Time Complexity: O(n^2)
    Space Complexity: O(1)

    Why It Won't Work Efficiently?
    Because:
    - Every pair is checked
    - Nested loops are slow for large arrays
    - Repeated unnecessary comparisons

    ==================================================

    OPTIMAL

    Idea:
    Use a hashmap to store visited numbers and their indices for constant-time lookup.

    Steps:
    1. Create an empty hashmap
    2. Traverse array
    3. Compute complement = target - current number
    4. If complement exists in hashmap, return indices
    5. Otherwise store current number with index

    Python Code:

    class Solution:
        def twoSum(self, nums, target):

            seen = {}

            for i in range(len(nums)):

                complement = target - nums[i]

                if complement in seen:
                    return [seen[complement], i]

                seen[nums[i]] = i

    Time Complexity: O(n)
    Space Complexity: O(n)

    Why It Works?
    Because:
    - Hashmap provides O(1) average lookup
    - Each element is processed once
    - Avoids checking all possible pairs
    
✅2. Valid Anagram (Hash Map / Frequency Counting)

    Explanation: Given two strings s and t, return true if t is an anagram of s, otherwise return false. An anagram contains the same characters with the same frequency.

    Input: s = "anagram", t = "nagaram"

    Output: True

    Clarifying Questions For Interviewer:
    1. Are the strings case-sensitive?
    2. Can strings contain spaces or special characters?
    3. Are we only dealing with lowercase English letters?
    4. Can strings be empty?
    5. Should we return boolean only?

    ==================================================

    BRUTE-FORCE

    Idea: Sort both strings and compare them.

    Steps:
    1. Convert both strings into sorted order
    2. Compare sorted strings
    3. Return comparison result

    Python Code:

    class Solution:
        def isAnagram(self, s, t):

            return sorted(s) == sorted(t)

    Time Complexity: O(n log n)
    Space Complexity: O(n)

    Why It Won't Work Efficiently?
    Because:
    - Sorting takes extra time
    - Unnecessary rearrangement of characters
    - Not optimal for very large strings

    ==================================================

    OPTIMAL

    Idea:
    Count frequency of characters using hashmap and compare counts.

    Steps:
    1. If lengths differ, return False
    2. Count frequency of characters in first string
    3. Decrease frequency using second string
    4. If any mismatch occurs, return False

    Python Code:

    class Solution:
        def isAnagram(self, s, t):

            if len(s) != len(t):
                return False

            freq = {}

            for ch in s:
                freq[ch] = freq.get(ch, 0) + 1

            for ch in t:

                if ch not in freq or freq[ch] == 0:
                    return False

                freq[ch] -= 1

            return True

    Time Complexity: O(n)
    Space Complexity: O(1)

    Why It Works?
    Because:
    - Frequency counting avoids sorting
    - Each character is processed once
    - Efficient linear-time comparison

✅3. Contains Duplicate (Hash Set / Linear Scan)

    Explanation: Given an integer array nums, return true if any value appears at least twice in the array, otherwise return false.

    Input: nums = [1,2,3,1]

    Output: True

    Clarifying Questions For Interviewer:
    1. Can the array contain negative numbers?
    2. Can the array be empty?
    3. Do we need to return the duplicate value or only boolean?
    4. Can we modify the array?
    5. Is extra space allowed?

    ==================================================

    BRUTE-FORCE

    Idea: Compare every element with all remaining elements.

    Steps:
    1. Pick one element
    2. Compare it with every next element
    3. If duplicate found, return True
    4. Otherwise continue checking

    Python Code:

    class Solution:
        def containsDuplicate(self, nums):

            for i in range(len(nums)):

                for j in range(i + 1, len(nums)):

                    if nums[i] == nums[j]:
                        return True

            return False

    Time Complexity: O(n^2)
    Space Complexity: O(1)

    Why It Won't Work Efficiently?
    Because:
    - Every pair is compared
    - Nested loops increase runtime heavily
    - Very slow for large arrays

    ==================================================

    OPTIMAL

    Idea:
    Use a hash set to track already seen elements.

    Steps:
    1. Create an empty set
    2. Traverse the array
    3. If current element already exists in set, return True
    4. Otherwise add it to set

    Python Code:

    class Solution:
        def containsDuplicate(self, nums):

            seen = set()

            for num in nums:

                if num in seen:
                    return True

                seen.add(num)

            return False

    Time Complexity: O(n)
    Space Complexity: O(n)

    Why It Works?
    Because:
    - Set lookup is O(1) on average
    - Each element is processed once
    - Detects duplicates efficiently

✅4. Group Anagrams (Hash Map / Frequency Counting)

    Explanation: Given an array of strings, group together all anagrams. Anagrams are words formed using the same characters with same frequency.

    Input: strs = ["eat","tea","tan","ate","nat","bat"]

    Output: [["eat","tea","ate"],["tan","nat"],["bat"]]

    Clarifying Questions For Interviewer:
    1. Are all strings lowercase English letters?
    2. Can input contain empty strings?
    3. Does output order matter?
    4. Can duplicate strings exist?
    5. Should grouped words preserve original order?

    ==================================================

    BRUTE-FORCE

    Idea: Compare every string with all other strings using sorted comparison.

    Steps:
    1. Maintain visited array
    2. Pick one string
    3. Compare with remaining strings
    4. Group strings having same sorted form

    Python Code:

    class Solution:
        def groupAnagrams(self, strs):

            def is_anagram(a, b):
                return sorted(a) == sorted(b)

            visited = [False] * len(strs)

            result = []

            for i in range(len(strs)):

                if visited[i]:
                    continue

                group = [strs[i]]
                visited[i] = True

                for j in range(i + 1, len(strs)):

                    if not visited[j] and is_anagram(strs[i], strs[j]):

                        group.append(strs[j])
                        visited[j] = True

                result.append(group)

            return result

    Time Complexity: O(n^2 * k log k)
    Space Complexity: O(n)

    Why It Won't Work Efficiently?
    Because:
    - Every string is compared with others
    - Sorting happens repeatedly
    - Very slow for large datasets

    ==================================================

    OPTIMAL

    Idea:
    Use character frequency as hashmap key to group anagrams efficiently.

    Steps:
    1. Create empty hashmap
    2. Build frequency count for each string
    3. Convert frequency list into tuple key
    4. Store strings having same key together

    Python Code:

    class Solution:
        def groupAnagrams(self, strs):

            groups = {}

            for word in strs:

                freq = [0] * 26

                for ch in word:
                    freq[ord(ch) - ord('a')] += 1

                key = tuple(freq)

                if key not in groups:
                    groups[key] = []

                groups[key].append(word)

            return list(groups.values())

    Time Complexity: O(n * k)
    Space Complexity: O(n * k)

    Why It Works?
    Because:
    - Same anagrams generate same frequency key
    - Hashmap groups related words instantly
    - Avoids repeated sorting operations

✅5. Longest Consecutive Sequence (Hash Set / Sequence Expansion)

    Explanation: Given an unsorted array of integers, return the length of the longest consecutive elements sequence.

    Input: nums = [100,4,200,1,3,2]

    Output: 4

    Clarifying Questions For Interviewer:
    1. Can the array contain duplicate numbers?
    2. Can numbers be negative?
    3. Can the array be empty?
    4. Do we only need the length or also the sequence?
    5. Is O(n) solution expected?

    ==================================================

    BRUTE-FORCE

    Idea: For every number, keep checking if next consecutive numbers exist.

    Steps:
    1. Pick each number
    2. Keep searching for next consecutive number
    3. Count sequence length
    4. Track maximum length

    Python Code:

    class Solution:
        def longestConsecutive(self, nums):

            longest = 0

            for num in nums:

                current = num
                count = 1

                while current + 1 in nums:
                    current += 1
                    count += 1

                longest = max(longest, count)

            return longest

    Time Complexity: O(n^2)
    Space Complexity: O(1)

    Why It Won't Work Efficiently?
    Because:
    - "in" operation on list is O(n)
    - Consecutive searching repeats many checks
    - Slow for large arrays

    ==================================================

    OPTIMAL

    Idea:
    Use a hash set and only start building sequence from numbers that are sequence starters.

    Steps:
    1. Store all numbers in a set
    2. Traverse each number
    3. If previous number does not exist, start new sequence
    4. Expand sequence forward
    5. Track longest sequence length

    Python Code:

    class Solution:
        def longestConsecutive(self, nums):

            num_set = set(nums)

            longest = 0

            for num in num_set:

                if num - 1 not in num_set:

                    current = num
                    length = 1

                    while current + 1 in num_set:
                        current += 1
                        length += 1

                    longest = max(longest, length)

            return longest

    Time Complexity: O(n)
    Space Complexity: O(n)

    Why It Works?
    Because:
    - Set lookup is O(1) on average
    - Each sequence is traversed only once
    - Avoids repeated unnecessary checks
